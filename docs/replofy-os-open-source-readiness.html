00 / Decision

Open source in two releases, not one big reveal.

LikelyThe lowest-risk route is a credible Firebase-backed developer preview first, followed by a cloud-optional self-hosted edition after the persistence and storage boundaries exist.

The uncomfortable answer

CertainIf you make the repository public now and call it self-hostable, early adopters will become unpaid integration testers for assumptions that currently live only on your machine. That creates support debt before community trust.

Recommendation

Prepare publicly; launch conditionally.
Ship a developer preview only after one-command local boot, seed data, dev auth, security fixes, license, and CI are proven from a clean clone.

03A / Data plan

Make local data boring, deterministic, and disposable.

LikelyThe first goal is not “replace Firebase.” It is “prove a complete workspace from zero state, repeatedly, without production credentials.”

Fast track · Firebase preview

Retain current behavior while removing founder-specific state.

  • Use an emulator-only demo project ID
  • Commit sanitized Auth + Firestore seed fixtures
  • Add idempotent seed and reset commands
  • Add a one-click local user and workspace
  • Commit Firestore indexes and test rules
  • Generate config from environment variables

Durable track · PostgreSQL

Build a true self-hosting substrate without a flag-day rewrite.

  • Define repository and provider contracts first
  • Move writes and reads behind application services
  • Design tenant keys, foreign keys, and audit fields
  • Version SQL migrations and seed fixtures
  • Replace realtime listeners with SSE or WebSockets
  • Provide backup, restore, and upgrade commands

Schema authority

Pick one executable source of truth. The current blueprint, TypeScript types, API configuration, and Firestore rules have already drifted apart.

  • Schema produces migrations, validators, and types
  • Runtime writes validate at the service boundary
  • Rules/policies are generated or contract-tested
  • Every new collection/table requires a migration

Files and AI

Local usefulness should degrade gracefully when optional providers are absent.

  • Filesystem driver for local assets
  • S3-compatible driver with MinIO in Compose
  • Cloudinary remains an optional adapter
  • AIProvider interface with disabled/mock mode
  • Quotas and authentication before provider calls
04 / Options

Choose the release promise before choosing the license.

LikelyYour most important product decision is whether the first public release promises transparency, contributor development, or full self-hosting. Those are different products.

Option A · Immediate

Publish the current repository

Fastest visibility, weakest first-run experience. Community attention is spent discovering local assumptions rather than improving the product.

Upside
Immediate transparency and signal
Downside
Security exposure, support burden, trust loss
Reversibility
Low once secrets/history and expectations are public
Reject
Option B · Recommended first release

Firebase-backed developer preview

Make a clean clone work locally with no cloud credentials, keep Firebase as the documented implementation, and label provider dependencies honestly.

Upside
Shortest path to a credible community release
Downside
Not yet cloud-agnostic or production self-hostable
Reversibility
High; adapters can evolve behind stable contracts
Choose now
Option C · Durable destination

Postgres self-hosted edition

Provide a standalone server, migrations, local auth, S3-compatible assets, backups, upgrades, and cloud-optional providers.

Upside
Real ownership, portability, and ecosystem potential
Downside
Largest engineering and maintenance commitment
Reversibility
Medium; becomes a supported platform contract
Build in stages
05 / Roadmap

Sequence work by trust, then portability, then scale.

LikelyThis order reduces the most uncertainty with the least irreversible work. It also creates a usable public milestone before the full database migration is complete.

0

Contain risk

Do before any public mirror or announcement.

  • Scan the full Git history for secrets and sensitive data; rotate anything questionable.
  • Authenticate Gemini; replace client-controlled first-admin bootstrap.
  • Inventory code, image, generated asset, brand, and dataset provenance.
  • Choose the license and trademark policy with counsel if the business model depends on hosted resale.
Exit gate · safe to expose history and artifacts
1

One-command local

Make the first 15 minutes reliable.

  • Add cross-platform dev:all, preflight checks, strict ports, health checks, and clean shutdown.
  • Use a demo Firebase project; remove production IDs and machine paths from defaults.
  • Commit sanitized seed fixtures, local login, reset, and representative workspace data.
  • Make Cloudinary and Gemini optional in local mode with explicit disabled states.
Exit gate · clean Linux and Windows clones pass first-run smoke
2

Public project surface

Turn a code dump into a maintainable project.

  • Add LICENSE, README rewrite, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, SUPPORT, and governance.
  • Rename and version the package; add repository metadata, changelog, and release policy.
  • Add CI for typecheck, unit, rules, API integration, clean bootstrap, secret scan, and license scan.
  • Publish a support matrix and “not supported yet” section.
Exit gate · developer preview release candidate
3

Extract platform contracts

Create seams without changing behavior first.

  • Introduce WorkspaceRepository, AuthProvider, AssetStore, AIProvider, and EventBus boundaries.
  • Move direct component writes behind application services and an API/query client.
  • Add standalone Node server, health endpoints, Dockerfile, and Compose.
  • Add filesystem and S3-compatible asset drivers; retain Firebase and Cloudinary adapters.
Exit gate · Vercel and local server pass the same contract tests
4

Self-hosted v1

Earn the label with operational proof.

  • Implement PostgreSQL schema and versioned migrations behind the repository contract.
  • Replace global realtime fan-out with bounded queries and explicit realtime transport.
  • Add backup, restore, upgrade, rollback, data export, and multi-tenant isolation tests.
  • Dogfood a fresh installation and upgrade from the previous tagged release.
Exit gate · self-hosting definition of done passes in CI
